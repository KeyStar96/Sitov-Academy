## Mapping contract

`lib/learning/sitov-topic-mapping.ts` version 1 is CONTENT METADATA ONLY. Seven sample topics connect actual A1.1/A1.2 anchors to stable vocabulary-card UUIDs/unit UUIDs, present-tense verb IDs and reading-text UUIDs from the existing authoritative repository catalogs. It contains no access grants, computed scores, fabricated mastery or second progress store. Full all-level thematic coverage is not claimed.

Anchor resolution must join `learning_units(level, trainer='exercises', is_path=true, path_source_id)` and `path_nodes(unit_id, source_id)`, require active published records, and return the actual UUID. Seed node IDs are **not** UUIDs. `35_path_learning.sql` imports units/nodes using database defaults and upserts by unit/source; generating replacement UUIDs would break existing IDs/progress. A zero/multiple-match resolver must fail closed. Published live catalog matching is still required; repository references do not prove live import or audio readiness.

Evidence sources: path-a1.1/path-a1.2 JSON node titles and goals; content/vocabulary/sitov-vocabulary-seed.json exact cards and units; lib/verbs/catalog-data.json and catalog.ts (cumulative catalog)/progression.ts; pronunciation-reading-2026.json exact unchanged UUIDs. Known existing evidence adapters: authenticated `getLearningPath` map/status via DB RPC; `sitov_verb_progress` per user/verb/tense; vocabulary cards/Leitner boxes and `loadLearningCheckpoint('vocabulary', level)`; `loadLearningCheckpoint('pronunciation', level)` plus S3 current-version individual pretest proof. Read actual current evidence, never mark vocabulary/verb/path progress from Special or pronunciation success. Pronunciation proof alone governs its pedagogical unlock; path anchors are recommendations only.

Proposed server port (needs M ownership/freeze): `resolveSitovLearningRecommendations({topicIds, failedCompetencyIds?, locale, limit})`. Auth account comes from server session. Resolve exact published IDs and canonical unit, call S1 current-user commercial guard for **each** target, omit denied/unknown/draft targets, read existing evidence/checkpoints, produce only meaningful authorized actions. No client account, access flag, score or URL is authoritative. A failure returns retryable error instead of invented zero progress.

S3/S4 result action DTO proposal: `{kind, level, targetId, unitId, topicId, competencyId, action:'start'|'resume'|'review'|'pretest', href}`. `href` is built by the server from an allocated exact-target route, locale and validated IDs. Existing trainer routes mostly do not consume exact-target parameters yet; **no start-page links are shipped as precise recommendations**. S3 uses failed competency IDs to request links; S4 renders localized action labels. A reading action is pretest/resume until its own current proof passes, then pronunciation. Neither path completion nor Special passage adds a pronunciation prerequisite.

## Proposed Special identity, trial and learning/test contract

Proposal for M/S1 freeze: typed `path_special` with actual `path_nodes.id` UUID; typed `path_special_item` with stored `learning_exercises.id` UUID. Canonical level/trainer/unit are looked up through the node and its anchor's existing `learning_units.id` (`trainer=exercises`); no new parallel access unit. Stable authored source identifiers use `sitov-special-<topic>-<level>-v1` and versioned item refs. Import upserts preserve resulting UUIDs; learner state/answers/streaks are not rewritten.

S1 guards both Special and each item (and every audio reference). Trial selected items determine eligible pool; it never implies all sibling items. null/all, []/none and selected semantics stay separate. If fewer than 20 authorized pool items support two disjoint balanced 10-item forms, test is unavailable with localized scope/content state; authorized learning cards can still be learned. Do not silently reduce test size, expose denied IDs/solutions, or reuse unauthorized samples. Start/resume/save/flip/grade all re-check publication and commercial item scope server-side.

Sidequest mode is explicit `learning` or `test`; no `test_size` on existing `special` nodes (currently invalid schema). Separate account-bound Special state/attempts and run revision: queue order, revealed current item, removed correct cards, request id, previous completed test item IDs. Learning self-assessment requires intentional reveal; right removes current card, wrong appends it; repeat request cannot count twice. Learning completion is learning feedback, not test proof. Test selects exactly 10 distinct balanced eligible examples; next form is disjoint from immediately previous 10, never leaks answers before grade, server grades 7/10 fail and 8/10 pass. All selected answers must match stored attempt version; CAS and idempotency protect concurrent tabs/repeated buttons. Persist failures and truthful targeted feedback. Green completion records an actual saved pass, not client self-score.

Completed anchor controls optional branch availability using existing node-availability semantics. Specials never enter main path required progress/tests, stars or points. Main completion stays unchanged. Main-path-free scope with no special remains a clear empty state. Publish requires editorial review and M's exact imported male-Qwen audio/timing proof for every audible German task; no runtime synthesis. This unit creates **zero** new audible text, so its audio manifest is empty; later authoring must freeze exact utterances before M serializes audio/import.

## Server contract

Service-only `public.sitov_revise_path_content(p_request_id uuid,p_items jsonb)` checks the actual invoking role, never JWT metadata. Each item is `{id, expected_hash, after, review}`. `after` must equal the server projection in every field except `content` and `translations`; stable UUID, unit/node UUID, type, goal, reference, order, topic and explanation-card reference cannot move. Projection = `path_private.snapshot(id)` plus unit_id/node_id/source_ref/sort_order/topic/explanation_card. Hash = PostgreSQL `encode(sha256(convert_to(projection::text,'UTF8')),'hex')`, not file/editorial SHA or client JSON serialization.

`translations` has de/en/ru/uk/tr objects with instruction/hint/explanation/prompt/task/gap_hint; preserve explicit null fields from server projection. `review` requires approved=true, reviewer, evidence_uri, exact before_hash and after_hash. This is a trusted service attestation bound to the exact server candidate; it does not independently verify a human or external editorial artifact. Obtain actual before projection/hash using privileged SQL before invoking. Candidate hash must also be computed with PostgreSQL JSONB, not guessed in JavaScript.

Exact whole-payload request replay returns its immutable receipt before inspecting the changed current version. Changed payload with the same UUID conflicts. Request lock precedes sorted existing catalog-level locks, sorted units and exercise UUID row locks, then locale locks. A failure raises, with no exception handler or partial success: the whole RPC transaction rolls back including content, audio reference writes, archive and receipt.

Private append-only archive records full exercise row/all translation rows before and after, both projections/hashes, request, exercise, actor role/time, reviewed evidence and server-resolved prepared-audio references. No foreign-key cascade can remove history. UPDATE/DELETE/TRUNCATE are rejected. App roles including service have no table/sequence privileges. Deferred constraint triggers additionally require every protected source at commit to equal its newest archive after-projection, covering other authoring routes and both old/new IDs on reassignment.

The shared importer is patched immediately after its existing catalog-level lock and before catalog writes. Protected tasks cannot be omitted, moved, reordered, retyped, assigned a different goal/ref, translated differently or have differing content/card/topic. Identical normalized current source is allowed. Existing SQL72 prepared-publication marker is required and its code remains installed. The writer independently invokes SQL71 authoritative saved-row audio validation, then resolves every nonempty German authoring leaf through the existing prepared male Qwen/timing helper, excluding IDs/type/audio URLs/UI instruction/target_form/gap_hint. This intentionally requires a superset (including options and fragments); the author must prepare these exact helper-normalized strings before application. No synthesis occurs in SQL. Keep old audio objects intact. Full after archive includes any SQL71 solution_audio_url update.

For protected IDs, `path_private.present` cannot fall back to current catalog gap_hint/task translations. Frozen snapshot values still display; missing optional help is omitted. No old snapshot is rewritten. Other IDs retain their old fallback.

# Sitov Academy — minimal shared protected-audio proposal

Proposal for M, epoch 2; no shared code changed.

1. Make `audio_cache` private and deny direct anonymous/authenticated storage object reads/metadata reads with a restrictive SELECT boundary. Ordinary content URLs currently point at `/object/public/audio_cache/`; these must stop working for locked references, even if an old URL or deterministic hash is known. Keep the actual prepared files and timing/profile metadata. Other audio trainers need their reads moved to the same authorized adapter before this switch; it cannot be deployed alone.
2. Extend German audio requests with a stable authored content reference, never trust caller text as permission. A pronunciation request is `{kind:'pronunciation',textId,textVersion}`; server reads the body under exact commercial + current-pretest guard and resolves the stored/prepared asset. Existing vocabulary cardId is already a partial content reference; preserve it and verify the actual German headword/chunk/example against authorized card data. M must add corresponding existing exercise/verb/path/daily/static-journey identifiers to its shared union and authorize them through their real current boundaries. Do not accept arbitrary de text as a fallback. Instructor authoring cache inspection stays a staff-only server operation.
3. For pronunciation, return a same-origin authenticated gateway URL, e.g. `/api/sitov-audio/pronunciation/<textId>?version=<textVersion>`, and validated word timings only **after** passage. The gateway checks the session, current commercial entitlement and exact version pass on every new request/Range request, reads the private prepared object with server credentials, and streams audio with validated byte ranges and content type. It must never redirect to a public object URL, expose service keys, leak metadata before passage or write German syntheses. `Cache-Control: private, no-store`; cross-account shared response caching prohibited. M may implement equivalent narrowly signed short-lived URLs, but must document the finite validity/revocation window and bearer sharing behavior instead of claiming continuous request authorization. An authenticated streaming gateway gives a direct before/after proof without bearer URL persistence.
4. Proposed server port: `resolveSitovAuthorizedGermanAudio(reference): Promise<{bucket,path,wordTimings,contentType}|machineError>` (server-only; bucket/path never in public DTO). `getSitovPronunciationReferenceAudio(textId,textVersion)` action returns `{audioUrl:gatewayUrl,wordTimings}` or `test_required|not_found|version_conflict|audio_unavailable`. `findCachedAudio` may still inspect imported proof for authors, but learner paths cannot use its current public URL result. M owns generic request/type/adapter/gateway changes; S3 supplies exact-version predicate/DB wrapper and tests, S4 calls the action and adapts playback/checkpoint.
5. Do not route `pronunciation_audio` learner/staff conversation playback through the new-learning guard. Participant access to submissions/messages and archived text snapshots remains the historical boundary. New recording tickets require current text proof; authorized audio replies use conversation-purpose tickets. A reply ticket can never create a new prompt submission. Old unsent blobs are preserved but give no recording/reference/pass rights.

Direct tests to add (real isolated DB/storage or native local service, distinct from Jest mocks): anonymous public URL access denied for an existing known cache path; authenticated direct storage read/download/info denied before passage; no metadata text/timings/key leak by REST private definitions or public wrappers; generic generateAudio({de,text:knownTarget}) denied; same catalog title does not expose body/URL; authenticated gateway refuses an old checkpoint/hard/VIP alone and a stolen foreign attempt; current proof allows exactly its text/audio/version without any learning rows; failure on a different text/version; removing commercial access blocks fresh gateway/Range/upload/submission despite proof; publication mutation lacks required audio metadata/timings/hash and remains draft; unrelated entitled vocabulary/verb/grammar/daily audio works after cache privatization; historical participant audio stays playable and never enables a new target upload.

Current isolated PGlite simulates storage rows/RLS but cannot prove public Storage HTTP behavior or streaming/range handling. M/S5 must explicitly provide that native service/browser evidence. Missing proof keeps RELEASE_READY false.

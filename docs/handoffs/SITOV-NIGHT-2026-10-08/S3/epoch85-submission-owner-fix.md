# Sitov Academy — submission definer ownership

The authenticated submission path can fail with `42501 permission denied for table upload_tickets` even after a valid upload. Migration 94 replaces the existing `pronunciation_private.create_submission(uuid,text)` body but PostgreSQL retains its legacy `postgres` owner. The new private ticket table belongs to the canonical `supabase_admin` migrator. SELECT authority alone does not permit the function's `SELECT ... FOR UPDATE` lock.

Migration 118 and its timestamped mirror perform one operation: change that function's owner to `supabase_admin`. They add no grants and do not replace the body, fixed search path, SECURITY DEFINER mode or existing authenticated EXECUTE permission. The individual PASS, current commercial authorization, ticket/source checks, source snapshot and historical receipt behavior remain in the existing function and trigger chain.

The other `pronunciation_private` function directly replaced by 94, `can_access_submission(uuid)`, reads existing submissions and calls the sealed staff helper. Migration 111 already addresses that helper's EXECUTE permission for the legacy postgres definer. Migration 110 handles the separate media-preservation helper call. This source review does not assert a blanket ownership audit of production functions.

Validation: `node --test supabase/tests/sitov-pronunciation-submission-owner.test.mjs` passed 8 tests on a fresh isolated socket-only PostgreSQL 17 cluster. The old and new application owner roles were both non-superusers. The fixture reproduced postgres having SELECT but no UPDATE on tickets, and the exact migration repaired the resulting native error. The unchanged migration-94 create function and submission trigger then consumed the same ticket exactly once, stored the source snapshot and returned the same submission on retry. Tests rejected foreign users/paths/texts, missing current PASS for new submissions, expired tickets, missing uploaded objects, anonymous execution and direct learner DML. Exact historical receipts remained available; function body/config/definer mode and API EXECUTE privileges stayed equal. The cluster was stopped and removed.

The existing native `sitov-pronunciation-pretests.test.mjs` suite also passed all 12 tests, covering individual prerequisites, commercial access, revocation, concurrent idempotency and historical preservation. These are synthetic native database regressions, not genuine GoTrue/MFA or production acceptance evidence.

S3 made no QA/production writes, new real actors, tickets, uploads or deployment. M received the minimal fix early for the already uploaded ticket. Shared migration-runner/schema edits were left to M; exact patches are private handoff artifacts. M owns the subsequent real authenticated continuation and release checks.

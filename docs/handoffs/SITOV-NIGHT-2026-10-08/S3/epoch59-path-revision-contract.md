## Minimal guarded update contract

1. Resolve actual database parents by `(level,path_source_id)` and `(unit_id,node.source_id)`, then exact exercise UUID/source_ref/goal/type. Require the old node and unit UUIDs, active flags and full catalog payload to match the reviewed manifest. The existing importer only prevents a foreign unit or null node; it can move an exercise between nodes in one unit. This revision must forbid that.
2. Before mutation, archive the exact database before-image: complete content, option/part order, correct/accepted answers, type, goal, refs, parent identities, all five translation rows, existing audio refs and any node context actually being changed. Preserve raw UTF-8 export/file SHA separately. Compute the version identity server-side over a specified JSONB projection encoded as UTF-8. Editorial sorted-JSON/source-file hashes in this report are not PostgreSQL JSONB version hashes. Archive both before and after revisions, including versions never selected by a student.
3. In one authorized transaction, acquire the existing level catalog lock, lock target rows in deterministic UUID order and compare expected parent plus before-version hash. A mismatch returns version_conflict without a write. Record reviewed after-image/audio proof and then update only the17 current content/translation rows. No deletion/reinsertion, no UUID/node/type/goal migration and no broad seed reimport that could move omitted rows or erase newer changes.
4. Do not touch practice_items.snapshot, test_items.snapshot, path_test_answers, answer_receipts, completed results, run queues, user_exercise_progress, node progress, streak/activity tables or real student/teacher recordings. Old achievements remain historical achievements; do not relabel them as a new-version test proof. New runs/attempts capture the new key; an ordinary start that resumes an old run correctly returns its old content. Do not force abandon/restart merely to replace a historical character.
5. A late answer bound to a still-valid old run is intentionally graded against its old snapshot. Fail closed on the wrong account/run/task, inactive/abandoned attempt, changed receipt payload or stale authoring precondition. Do not reject a valid historical answer merely because current catalog content changed. Existing learner signatures need no extra catalog-version parameter.
6. Keep audio object references immutable: retain old recordings for old snapshots and prepare/import exact new German texts with timings before publication. Never overwrite an old audio object under the same URL. Check full options/context, not only the correct answer. Keep the common SQL72 prepared-audio guard.
7. Audit affected Specials before writing. Their definitions are immutable, include full snapshots and compare them to current `path_private.snapshot`; a mismatch intentionally yields version_conflict. Create a new immutable definition/version and fresh editorial/source/audio proofs through the existing publication flow. Never rewrite old definitions, runs, receipts or proof hashes. Old Special rows remain stored, but the existing operation requires a ready currently activated definition even for `get`: continued access/resumption of an affected old Special is not guaranteed. Resolve that dependency before advertising historical-read/resume availability; do not weaken the current-source guard or silently regrade against new options.

For a durable server-enforced revision workflow, request M allocation114 for only: an append-only private per-exercise source-revision ledger; a privileged CAS writer using the existing catalog locks and exact parent/content/translation hash; a narrow check in the shared catalog importer rejecting attempts to overwrite a ledger-protected revision with a different payload outside the reviewed writer; and the scoped legacy-help fallback change below. Reuse existing practice/test snapshot tables and learner RPCs unchanged. This is a request, not an allocated migration filename or implemented schema.

Minimum ledger record: stable exercise ID, canonical parents/ref/type/goal, version hash, previous-version hash, full snapshot/translation/context payload, editorial/audio evidence, actor/time and idempotent request identity. Private access, immutable update/delete guard, no cascade deletion of old revisions. The writer rejects stale expected hash/identity; identical request retries replay the receipt, differing payload reuse conflicts. Preflight and final same-transaction checks retain all existing content/audio validation. The generic importer may still import identical current payloads, but must not regress a protected current revision. An operational one-off locked CAS plus externally verified before/after archive can preserve this batch without a new learner architecture; it is not a durable server-enforced authoring revision contract by itself.
